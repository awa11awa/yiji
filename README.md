# 忆迹 v2.0.0

Android 本地通知日程管理应用。内置中文 TinyBERT 4L-312D 模型，无需账号、联网或模型服务，即可筛选通知、分类并生成待确认事项。

## v2 的识别方式

选定来源的每条文字通知都进入模型。模型联合输出是否为待办、事项类别、时间角色、日程状态和新建／变更／取消意图；已删除 v1 云端 AI 增强、关键词名单、规则分类器与后端服务。APK 不申请 INTERNET 权限。

支持作业、报名、会议、课程、活动、考试、材料和其他类别。模型区分开始、结束、截止与背景日期，一条通知可以生成多条草稿。例如活动时间和报名截止分别核对，确认一项不会隐藏其余待确认项。

日历代码只换算模型选出的时间表达（例如“明天”“本周日”“今晚23.52”），并校验日期和时间是否有效。相对日期以通知真实接收时间及手机时区为准；未写年份会提示核对。具体时刻缺失、面试另行通知或个人需要预约时保留空值，不生成当天、全天或默认结束时间。

分类与时间识别仍可能有误，所有新建、更新和取消建议均需用户确认。模型识别失败时保存原文并提供重试，不回退关键词规则。

## 安装与使用

在 [GitHub Releases](https://github.com/awa11awa/yiji/releases) 下载 `yiji-v2.0.0-debug.apk`。支持 Android 8.0（API 26）及以上。当前交付为开发测试包，签名可能与旧版不同；升级前请在旧版导出备份。

粘贴／分享通知文本后，到通知箱逐项核对模型结果。作业类别也会进入独立作业栏。具体时间补齐后才能保存提醒。自动采集需在系统中授权通知读取，并在设置中选择来源应用、开启采集。

来源选择、暂停、同一来源标题正文 24 小时去重、备份恢复、来源历史、变更关联和时间冲突检测继续保留。用户主动搜索列表、按类别查看事项不属于自动关键词筛选。自动接入仅能读取系统通知中可用的文字；本版不包含 OCR，也不读取应用聊天数据库。

## 构建与验证

需要 JDK 17 或 21、Android SDK 35 / Build Tools 35.0.0。标准命令：

```sh
./gradlew --no-daemon --console=plain --max-workers=2 testDebugUnitTest lintDebug assembleDebug
```

如本地仅安装 `android-35-ext15`，附加 `-Pyiji.sdkExtension=15`。受限网络可附加 `-I scripts/mirrors.init.gradle.kts`，Robolectric 镜像使用 `-Pyiji.testRepo=https://repo.huaweicloud.com/repository/maven/`。

测试包括实际 INT8 模型的 Java 推理、时间归一化、多草稿独立处理、模型失败重试、旧设置迁移、Room/备份、通知监听与 Compose 导航。JVM 测试使用桌面 ONNX Runtime 原生库；APK 使用同版本 Android 库。自动测试不能替代真机通知送达和性能测试。

`v2.0.0` 分支的发布工作流在测试、Lint、构建、签名与版本检查通过后发布开发测试 Release，附 APK、源码 ZIP、更新说明及 SHA256SUMS.txt。

## 模型资料

模型、词表与标签元数据在 `app/src/main/assets/tinybert/`。架构、来源、训练范围、量化验证和局限见 [模型说明](model/MODEL_CARD.md)，训练与导出工具在 `model/tools/`。模型首次使用时从 APK 加载，之后在进程内复用。

数据库和备份继续使用 v1 结构；已确认的旧事项不会重新分类。升级时清除旧服务令牌、服务地址、AI 开关和忽略关键词设置。
