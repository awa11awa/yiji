# 忆迹 v2.2.1

《忆迹——基于多源通知语义关联与时序冲突检测的重要事项智能管理系统》Android 应用。

本版使用“两阶段识别”：内置 TinyBERT 在手机上筛选聊天／日程候选；日程候选交给用户自己配置的云端 API 模型，提取作业、活动、会议、报名截止等事项。默认预设智谱 GLM-4.7-Flash，不内置开发者密钥，不需要自建后端。

## 开始使用

1. 安装正式版 yiji-v2.2.1.apk，支持 ARM64、Android8.0及以上。
2. 打开“设置 → API与模型 → 获取免费API·操作教程”。
3. 在智谱开放平台创建自己的 API Key，编辑默认智谱配置，填写密钥。
4. 测试连接、保存配置，开启云端识别并阅读发送内容说明。
5. 粘贴、分享通知，或在设置中授权通知读取并选择来源应用。
6. 通知箱逐项核对，确认后才新建、更新或取消事项。

API基础地址：https://open.bigmodel.cn/api/paas/v4
默认模型：glm-4.7-flash

## 多 API 配置

参考 CC Switch 的“多套配置＋快速切换”交互独立实现，未复制其源码或资源。可以添加、编辑、删除多套服务配置，切换当前配置；每套包含名称、HTTPS基础地址、API Key、模型名称。内置智谱与硅基流动预设，支持自定义 OpenAI兼容 Chat Completions 接口。可获取模型列表，也可手动填写模型名；连接测试实际请求一段固定 JSON 测试，不发送通知原文。

密钥通过 Android Keystore 中的 AES-GCM 密钥保护本机存储，不写入APK、日志或导出备份。请求直接发送给用户选择的模型服务商，不经开发者服务器。关闭云端或没有配置密钥时，候选原文保留待提取；不回退旧的本地规则抽取。

免费价格与额度由服务商决定。模型列表可能包含收费型号，应用不自动切换收费模型。具体获取步骤和失败处理见应用内教程及 API_GUIDE.md。

## 消息处理

- 先在 Room 保存原文和持久任务，再由 WorkManager 筛选、提取；识别期间不占用事项编辑锁。
- 聊天原文留在已忽略列表，不自动发给云端；本地不确定内容保留为候选。讲坛、讲座与安排调整等明确校园通知增加漏识别保护，只改变候选路由，不在本地编造时间地点。
- 云端明确判为非待办时进入已忽略；正文截断、含义不清或与重要通知特征冲突时保留待核对。时间地点不全、另行通知也可以生成草稿并确认保存为待补时间。可手动整理或主动忽略通知。升级时恢复旧版自动忽略的云端结果和有重要通知特征的本地结果，等待你核对，不自动重发。
- 开启上下文时，仅提供最多4条同应用、同通知标题、24小时内且不晚于当前接收时间的日程候选，以及最多8个相关已确认事项。普通聊天和其他群消息不作为上下文。
- 通知标题不是完整聊天会话标识，仍可能有同名歧义；可关闭上下文，并始终核对关联目标。
- 云端为每个事项独立输出类别、类型、操作、关联目标及原文证据。时间由客户端根据原消息接收时间与时区换算。
- 缺失时间留空；不自动生成23:59、全天或默认结束时间。没有依据的时间和地点被留空并提示。
- 缺少Key、网络错误、限流、模型结果不合规均保留原文，区分等待配置、自动重试和手动重试。使用流式接收，兼容普通JSON响应；单次请求最多3分钟，连接15秒/读取空闲90秒，取消会断开连接。最多请求3次（首次加2次自动重试），至少60秒指数退避，遵循服务端 Retry-After；正在处理的任务不能被重复重试覆盖。
- 已忽略消息可以主动送云端复核。新建、更新和取消均须人工确认。
- 采集时使用系统提供的扩展正文，对能够确认属于同一消息的摘要进行补全，保留多条消息各自的来源时间。展开后显示已采集正文和字数，支持选中复制。疑似截断时明确提示，可点“补全正文”粘贴完整消息并重新识别，保留原记录及接收时间。
- 系统通知接入无法读取未提供或隐藏的正文。QQ 可使用本版内置的平板协议接收端，选择会话后直接接收消息；本版不包含 OCR 或聊天数据库读取。

## v2.1.2 提取与保存规则

- 云端默认输出版本2协议，兼容解析旧协议；完整字段约定见 [CLOUD_PROTOCOL_V2.md](CLOUD_PROTOCOL_V2.md)。
- 报名开放和截止分别保存、分别提醒；只有开放时间时不生成截止时间。
- 更新区分保留、替换、待定、清除。确认时间待定后撤销旧提醒，历史仍保留；编辑器选择关联目标时遵守相同规则。
- 原文证据兼容NBSP、换行和允许的全半角差异，唯一匹配后映射回原文位置。数字或文字发生变化、来源错误和多处歧义仍需核对。
- 开始时间明确、结束未知的日程可确认保存并安排开始提醒。日期精度和待定事项可以保存，补全时刻后再安排时间提醒。冲突检查只覆盖完整区间。
- 同一份作业包含可勾选子任务、选做标记和各项截止；整体确认后仍是一条作业。子任务完成、历史与备份均保留。

## v2.1.3 模型兼容与未读提醒

- GLM-5.3/Flash/FlashX 按官方要求开启思考，使用轻度推理并给连接测试留足输出空间；默认 GLM-4.7-Flash 保留既有参数。其他模型使用通用请求参数，不按服务商域名统一强加关闭思考等选项。应用不自动更换模型。
- HTTP 400 显示结构化服务错误码与经过密钥脱敏的原因，区分参数、模型名称和接口不兼容；非 JSON 错误页不直接展示。
- 作业“待完成”“待确认”“已逾期”“已完成”“已取消”分别筛选；只有“全部”同时展示草稿和正式事项。日期精度截止与未完成子任务的截止也参与逾期判断，日期当天不会提前算逾期。
- 作业、事项和通知箱状态按钮带未读红点，底部入口汇总未读数量。打开对应栏目后，将当前搜索/类别筛选下列出的记录标为已读；其他栏目保持未读。新增、修改、状态变化或首次转逾期会重新提醒，已读记录在重启后保留。已读和任务完成相互独立。
- 未读记录只在本机保存标识和版本摘要，不改写事项状态，不进入导出备份。没有新内容时，重新进入栏目不会再次亮点。

## v2.1.4 持续采集与耗电

- 开启采集并授权、选择来源后，默认开启持续采集保护，显示无声常驻通知，可从通知暂停。使用 `specialUse` 前台服务，划掉应用界面不会主动停止保护；开机、应用更新后在系统允许时恢复。关闭保护仍可使用系统通知监听，暂停采集会同时停止保护和恢复任务。
- 启动及回到前台统一检查监听，断开后按2秒、10秒、30秒、1分钟、5分钟逐步退避重试，恢复后取消重试。保护运行时每5分钟进行一次不唤醒设备的连接检查，正常连接不会反复扫描通知栏；另有30分钟周期、10分钟弹性窗口的系统调度兜底，不保证准时执行。
- 连接建立后补采仍在通知栏的所选来源，自动补采30秒节流，手动补采1秒节流；来源变更和重新建立连接允许立即补采，原有数据库去重继续生效。
- 保护服务不持有唤醒锁，不使用精确闹钟、网络心跳或常驻模型推理。先保存原文再由持久队列识别；TinyBERT保留原有线程上限并关闭线程池空转，模型权重与识别阈值不变。
- 应用列表只在选择来源时于后台线程加载，避免每次进入设置页阻塞界面。设置页显示保护状态，提供系统电池设置入口。
- 系统强行停止、撤销权限、厂商后台清理仍可能中断。允许后台运行、自启动并锁定最近任务可改善存活；不会绕过用户停止操作。已消失的通知与未发布为系统通知的聊天消息无法补采。后台存活率和电池消耗需在实际设备上长期验证，不能承诺不漏采或固定耗电百分比。

## 模型与训练

本版从保存的权重继续训练 CHAT/SCHEDULE 通用消息二分类 TinyBERT，加入脱敏通知及工作、学习、生活消息，模型约45.60MB。真实通知按活动分组，合成句式分开；开发集已用于多轮迭代，不能当作独立真实消息准确率。完整选择过程见 [模型说明](model/MODEL_CARD.md) 和 [训练报告](model/message_bert_training_report_v2.2.1.json)。Release 附独立模型 ZIP，与 APK 使用同一份权重。

## 数据兼容

Room数据库支持1→2→3及2→3升级，新增开放时间、时间语义和子任务，保留事项、原文、来源与历史。旧版尚无草稿的待处理原文可进入新队列。导出备份格式为2，继续支持导入格式1；API配置、密钥、系统权限与来源选择不在备份中。恢复的未提取原文会重新排队。

从 v2.1.0 起，发布 APK 使用同一固定签名密钥，与此前交付的 v2.1.0 安装包一致；后续版本沿用此签名，可直接覆盖升级。v2.0.0 及更早版本的签名可能不同，首次迁移前先在旧版导出备份并保存到应用外；若提示签名不一致，保存好备份后再卸载旧版、安装新版并恢复。

## 构建与验证

需要 Python3、JDK17/21、Android SDK35 与 Build Tools35.0.0。

    ./gradlew --no-daemon --console=plain --max-workers=2 testReleaseUnitTest lintRelease assembleRelease

仅有SDK扩展安装时可附加 -Pyiji.sdkExtension=15。网络镜像配置见 scripts/mirrors.init.gradle.kts。Android构建从 model 目录的固定压缩分片还原已导出的模型并校验SHA-256，不触发重新训练；还原脚本只使用Python标准库。

测试覆盖：实际部署模型的二分类推理、云端接口契约与错误处理、逐事项原文校验、独立操作与关联、API配置切换与保密、持久队列与中断恢复、旧库迁移、通知监听、备份及Compose导航。真实服务调用需用户自行填写有效Key；自动化测试不使用用户密钥，不证明真机网络、通知送达或云端识别准确率。

发布工作流从 GitHub Actions Repository Secrets 恢复固定签名，并校验证书 SHA-256；缺少密钥或证书不匹配时停止发布。密钥、密码和备份包不进入公开源码或 Release。开发者本地恢复及发布约定见 RELEASING.md。
